# ПОЛНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ CHATGPT CODEX
# Проект: «РУССКИЙ ROYALE»
## Многопользовательская образовательная платформа для подготовки к ЕГЭ по русскому языку

## 1. ТВОЯ РОЛЬ И ГЛАВНАЯ ЦЕЛЬ

Ты — опытный full-stack разработчик, архитектор программного обеспечения, UI/UX-дизайнер, разработчик браузерных игр и специалист по образовательным платформам.

Твоя задача — самостоятельно создать полноценный веб-проект «РУССКИЙ ROYALE».

Это образовательная игровая платформа для школьников, готовящихся к ЕГЭ по русскому языку.

Над проектом работают четыре человека. Мы хотим самостоятельно добавлять правила русского языка, задания, примеры, слова, объяснения и пробные экзамены. Программировать каждое новое правило мы не должны.

Важнейшая идея проекта — объединить подготовку к ЕГЭ с популярными многопользовательскими играми.

Наша аудитория — школьники 10–11-х классов.

Мы хотим, чтобы пользователь мог как самостоятельно заниматься, так и соревноваться с друзьями в реальном времени.

**Главный принцип: это настоящая игровая платформа, а не обычный сборник тестов, замаскированный под игры.**

Ты должен создавать реальный работающий проект в рабочей директории, а не только описывать будущую разработку.

Работай самостоятельно, принимай разумные технические решения, создавай необходимые файлы, устанавливай зависимости, проверяй код и исправляй ошибки.

Если для какой-то функции требуется внешний сервис или действие владельца проекта, подготовь всё остальное, а затем объясни, что необходимо сделать.

Не объявляй неработающие функции готовыми.

## 2. ТЕХНОЛОГИИ И ОБЩИЕ ТРЕБОВАНИЯ

Проект должен работать через браузер.

Никаких обязательных установок из App Store или Google Play.

Он должен работать на:

- Windows.
- macOS.
- Android.
- iPhone.
- Планшетах.

Сделай адаптивное веб-приложение с поддержкой PWA, чтобы сайт можно было добавить на главный экран телефона.

Предпочтительный стек:

Frontend:
- React.
- TypeScript.
- Vite.
- Tailwind CSS.
- Современные библиотеки компонентов и анимаций.

Backend:
- Supabase.
- PostgreSQL.
- Supabase Auth.
- Supabase Realtime.
- Supabase Storage.
- Серверные функции для игровой логики.

Тестирование:
- Vitest.
- Playwright.
- Тесты серверной логики.

Если более подходящий стек позволит сделать проект надёжнее, можешь выбрать его, но объясни техническую причину.

Основной язык интерфейса — русский.

Цель — поддерживать до 30 одновременно подключённых игроков в одной игровой комнате, если конкретный режим допускает такое количество участников.

# 8. ДЕСЯТЬ ИГРОВЫХ РЕЖИМОВ

В проекте необходимо предусмотреть десять полноценных игровых режимов.

Каждый режим должен иметь собственную механику.

Учебные задания должны дополнять геймплей, а не уничтожать оригинальный смысл игры.

Все задания и правила должны браться из административной базы.

## ИГРА 1. «ШПИОН»

Это приоритетная игра для первой рабочей версии.

Игроки присоединяются к комнате.

Ведущий запускает игру.

Система выбирает секретную тему из базы правил.

Все обычные игроки получают одну тему.

Шпион получает только общую категорию.

Например:

Обычные игроки видят:

«Орфография — Суффиксы -ЕК- и -ИК-».

Шпион видит:

«Орфография. Ты шпион. Попытайся угадать тему».

Игроки обсуждают тему и задают вопросы.

Обычные игроки пытаются обнаружить шпиона.

Шпион пытается понять секретную тему.

После обсуждения начинается голосование.

Если шпиона обнаружили, он получает возможность назвать секретную тему.

Условия победы должны быть явно определены.

Для первой версии:

- Если большинство проголосовало за невиновного, побеждает шпион.
- Если большинство правильно определило шпиона, он может попробовать угадать тему.
- Если шпион правильно угадал тему, побеждает шпион.
- В противном случае побеждают обычные игроки.

Реализуй правила на случай ничьей и истечения времени.

Добавь таймеры, карточки ролей, анимации и экран результатов.

В последующих версиях предусмотрены дополнительные режимы:

- Два шпиона.
- Шпион со словами.
- Шпион с грамматическими правилами.
- Сложный режим.

## ИГРА 2. «МАФИЯ»

Создай полноценную многопользовательскую «Мафию».

Роли:

- Мафия.
- Мирный житель.
- Доктор.
- Комиссар.

Основной цикл:

Ночь → действия ролей → день → обсуждение → голосование → следующий раунд.

Учебные задания используются для получения преимуществ.

Например:

Комиссар должен правильно выполнить задание, чтобы получить результат проверки.

Доктор должен решить орфографическую задачу, чтобы применить лечение.

Мафия может получать ограниченный игровой бонус за правильный ответ.

Сохрани стратегию и психологическую часть игры.

Добавь настройки количества ролей и времени обсуждения.

## ИГРА 3. «БУНКЕР»

Создай игру на основе социального обсуждения, убеждения и голосования.

Игроки получают карточки:

- Профессия.
- Возраст.
- Здоровье.
- Навык.
- Багаж.
- Дополнительный факт.

Каждая партия имеет сценарий катастрофы.

Количество мест в бункере ограничено.

Игроки раскрывают характеристики, обсуждают свои преимущества и голосуют.

Правильное выполнение задания по русскому языку позволяет получить небольшой игровой бонус.

Например:

- Открыть дополнительную характеристику.
- Получить право на ещё один аргумент.
- Заменить одну карточку.
- Получить иммунитет на один этап, если такая настройка разрешена.

Все характеристики и сценарии должны быть редактируемыми через админку.

## ИГРА 4. «ДУРАК»

Создай карточную игру с понятной механикой обычного «Дурака».

Игроки получают карты.

Есть козырная масть.

Игроки ходят, защищаются, подкидывают карты и добирают колоду.

Добавь учебную механику:

При определённых действиях появляется вопрос по русскому языку.

Правильный ответ позволяет получить предусмотренный бонус или выполнить специальное действие.

Неправильный ответ приводит к заранее установленному последствию.

Сохрани карточный характер игры.

Не превращай «Дурака» в простую викторину.

Поддерживай подходящее для карточной механики количество игроков.

## ИГРА 5. «САМОЗВАНЕЦ»

Игроки получают похожие грамматические темы.

Большинство получает одну тему.

Один игрок получает другую.

Например:

Большинство — «Н и НН в прилагательных».

Самозванец — «Н и НН в причастиях».

Игроки приводят примеры и обсуждают правила.

Затем голосуют за предполагаемого самозванца.

Создай механику определения победителя.

## ИГРА 6. «КТО Я?»

Игрок получает скрытое слово или грамматический термин.

Другие участники знают этот термин.

Игрок задаёт вопросы, на которые можно отвечать «да» или «нет».

Цель — угадать термин.

Примеры:

- Причастие.
- Деепричастие.
- Сказуемое.
- Метафора.

Слова и термины загружаются администраторами.

Добавь таймер и систему очков.

## ИГРА 7. «ALIAS»

Командная игра с объяснением терминов.

Один игрок получает слово.

Он должен объяснить его своей команде, не называя сам термин и запрещённые слова.

Другие пытаются угадать.

Добавь таймер, команды, очки и переход хода.

Администратор должен добавлять карточки со словами и запрещёнными выражениями.

## ИГРА 8. «РУССКАЯ РУЛЕТКА»

Игроки получают случайные задания.

Каждый раунд становится сложнее.

Можно использовать режимы:

- На выбывание.
- На очки.
- На скорость.

Добавь визуальную анимацию рулетки.

Побеждает игрок, который остаётся последним или набирает больше всех баллов, в зависимости от режима.

## ИГРА 9. «СВОЯ ИГРА»

Командная интеллектуальная викторина.

Покажи игровое поле с категориями и стоимостью вопросов.

Например:

Орфография — 100, 200, 300, 400, 500.

Пунктуация — 100, 200, 300, 400, 500.

Лексика — 100, 200, 300, 400, 500.

Игроки выбирают вопросы.

Команды соревнуются за баллы.

Реализуй механику очередности, проверки ответов и определения победителя.

## ИГРА 10. «ИСПОРЧЕННЫЙ ТЕКСТ»

Игроки получают текст с ошибками.

Их задача — найти и исправить ошибки.

Предусмотри режимы:

- Каждый за себя.
- Команды.
- На скорость.
- По очереди.

Проверяй исправления по данным, предоставленным администраторами.

Показывай объяснения после завершения.

Не жди, пока я пришлю фотографию.

Создай оригинального персонажа в стиле качественного pixel art.

Внешность:

- Женщина средних лет.
- Строгая, но доброжелательная.
- Очки.
- Выразительная мимика.
- Классическая одежда учительницы.

Если генерация изображений недоступна, самостоятельно создай оригинальный SVG или pixel-art ассет, который можно использовать в проекте. Не подставляй произвольные изображения из интернета.

4. Удивлённое.
5. Объясняющее.

Для первой версии допустимы простые анимации и изменение выражений лица.

### 9.1. Как проходит урок

Ученик открывает правило.

Появляется пиксельная учительница.

Рядом возникает диалоговое облако.

Например:

«Так, мои дорогие, сегодня разбираемся с суффиксами!»

Пользователь нажимает «Далее».

Учительница перемещается в сторону.

Появляется изображение с примерами.

Затем выводится объяснение.

После объяснения появляется интерактивное задание.

Например:

«Вставь букву: замоч_к».

Ученик отвечает.

Если правильно, персонаж радуется.

Если неправильно, персонаж даёт забавный комментарий и объясняет ошибку.

Юмор должен быть доброжелательным, без унижений учеников.

### 9.2. Редактор уроков

Администратор должен иметь возможность создавать уроки из отдельных блоков:

- Диалог.
- Изображение.
- Объяснение.
- Пример.
- Интерактивное упражнение.
- Проверка.
- Анимация.
- Результат.

Реализуй возможность переставлять блоки и изменять их содержание.

### 9.3. Замена персонажа

Это обязательная функция.

Позже я пришлю реальную фотографию нашей учительницы и подготовлю на её основе новое изображение.

Мне нужно будет просто зайти в административную панель и заменить изображения персонажа.

Обязательно предусмотрите:

- Загрузку изображений.
- Предпросмотр.
- Замену текущего персонажа.
- Управление изображениями для разных эмоций.
- Редактирование реплик.
- Сохранение изменений.

Персонаж не должен быть жёстко встроен в код.
