# Развёртывание

Текущий код рассчитан на **один Node.js-процесс с постоянным диском**. Статический `dist/` без API не является рабочим приложением. Сайт опубликован отдельно на Cloudflare: https://russian-royale.russian-royale.workers.dev. Актуальный способ обновления облачной версии описан в [CLOUDFLARE.md](CLOUDFLARE.md); ниже приведены альтернативы для исходного Node-сервера. Конфигурация Docker/Caddy подготовлена; Docker в текущей среде отсутствует, поэтому контейнерная сборка и HTTPS на реальном домене ещё не проверены.

## Вариант A — сервер с Node.js

1. Выделите Linux/Windows-сервер с Node.js 24.15+ (24.x), постоянным диском и доступом к домену. Стоимость зависит от выбранного хостинга; для локального тестирования облачный тариф не требуется.
2. Перенесите проект без `node_modules`, `.env`, тестовых данных и личных `data/`. Для существующей рабочей базы переносите `data/` отдельно через резервную копию. Не публикуйте его в Git.
3. Установите pnpm 11.25.0: `npm install -g pnpm@11.25.0`. Затем `pnpm install --frozen-lockfile`, `pnpm build`.
4. Создайте `.env`: `NODE_ENV=production`, `DATABASE_PATH` и `UPLOADS_DIR` указывают на постоянный диск. `PUBLIC_ORIGIN=https://ваш-домен`, `TRUST_PROXY=1`, `COOKIE_SECURE=true` применяются за одним доверенным HTTPS proxy.
5. Запускайте `npm start` как системную службу или процесс с автоматическим перезапуском. Только **один экземпляр**, без cluster mode.
6. Поставьте перед приложением Caddy или другой HTTPS reverse proxy. Пример Caddy ниже. Порт API не выставляйте напрямую в интернет. Proxy должен пропускать SSE и не буферизовать поток.
7. Зарегистрируйте собственный аккаунт через публичный адрес и выполните `npm run admin -- email` на сервере. Не назначайте администратором случайный первый аккаунт.

Пример Caddy для Node на том же сервере:

```caddy
royale.example.org {
  reverse_proxy 127.0.0.1:3001 {
    flush_interval -1
  }
}
```

DNS A/AAAA домена должен вести на сервер. Для автоматического HTTPS Caddy нужны корректный DNS и открытые порты 80/443. Проверяйте условия и лимиты выбранного хостинга, постоянство диска и поддержку долгих SSE-соединений.

## Вариант B — Docker Compose + Caddy

На Linux-сервере установите Docker с Compose. Создайте `.env` в каталоге проекта:

```dotenv
DOMAIN=royale.example.org
```

Замените только значение домена на свой. Затем:

```sh
docker compose up --build -d
docker compose logs --tail=50 app
```

Сайт: `https://ваш-домен/`, админка: `https://ваш-домен/admin.html`.

После регистрации администратора:

```sh
docker compose exec app node node_modules/tsx/dist/cli.mjs server/admin-cli.ts ваш@email.ru
```

Рабочая база и загруженные картинки находятся в persistent volume `royale_data`; сертификаты — в `caddy_data`. Обновление: `docker compose up --build -d`. **Не используйте `down -v` для обычного обновления:** это удаляет volumes с данными. Сначала сохраняйте резервную копию.

## Проверка перед приглашением друзей

Откройте сайт с двух независимых браузеров, зарегистрируйте аккаунты, создайте сервер и проверьте ссылку приглашения. Для запуска раунда нужны три участника. Проверьте отображение роли после обновления страницы, чат и голосование. Убедитесь, что URL приглашения содержит общий публичный домен. В PWA-режиме также должен использоваться этот домен.

## Резервные копии

Из каталога проекта:

```powershell
npm run backup
```

Команда создаёт согласованную SQLite-копию через `VACUUM INTO` и копирует каталог uploads в `data/backups/<время>`. Изображения только добавляются с уникальными именами; удаление контента не удаляет исходный файл из uploads, поэтому его копирование после снимка БД сохраняет все ссылки снимка. Храните резервные копии отдельно от основного диска; они содержат персональные данные и хеши сессий/паролей.

В Docker:

```sh
docker compose exec app node node_modules/tsx/dist/cli.mjs scripts/backup.ts
```

Для восстановления остановите приложение, сохраните текущую `data/` в отдельное место, замените БД и uploads из выбранной копии, удалите только относящиеся к заменяемой остановленной БД файлы `-wal`/`-shm`, затем запустите приложение. Проверьте вход, урок и изображения. Не подменяйте живой SQLite-файл во время работы сервера.
