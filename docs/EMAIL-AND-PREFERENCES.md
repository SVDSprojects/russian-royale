# Почтовые коды и настройки интерфейса

## Настройка отправки

Используется Brevo Transactional Email API https://api.brevo.com/v3/smtp/email. Аккаунт и подтверждённый отправитель принадлежат владельцу сайта. Отправитель задаётся через MAIL_FROM, ключ через BREVO_API_KEY, случайный HMAC-секрет минимум 32 символа через AUTH_CODE_SECRET. Все три значения сохраняются как Cloudflare Worker Secrets; в публичный GitHub их не добавлять. API-ключ вводится только в Cloudflare Settings → Variables and Secrets. Не использовать SMTP password вместо API key. Подтверждение отправителя и ограничения домена проверяются по правилам Brevo: https://developers.brevo.com/docs/getting-started-with-senders-and-domains.

В Node те же настройки можно задать в локальном .env. Не вставлять значения в команды, которые сохраняются в истории или логах. После изменения Worker Secrets опубликовать текущую версию с обновлением Durable Object и проверить /api/auth/status. Наличие настроек само по себе не подтверждает доставку: требуется получить настоящее письмо.

## Регистрация и восстановление

SMS-провайдер отсутствует; выбран разрешённый владельцем вариант с почтой. После настройки отправителя регистрация требует шестизначный код. Существующие пользователи продолжают вход по паролю. Восстановление также требует код и новый пароль, затем завершает все прежние сеансы пользователя. Коды действуют 10 минут, допускают 5 проверок, используются однократно. Хранятся HMAC-хеши с nonce, а не открытые коды. Повторная отправка — минимум через 60 секунд, максимум 6 писем в час на адрес и 30 на IP. Ответ на запрос восстановления не раскрывает наличие аккаунта. Код регистрации не подходит для сброса пароля.

До первого подключения почты обычная регистрация работает без кода; форма честно сообщает об отсутствии отправки, восстановление по коду недоступно. После первого включения обязательность кодов сохраняется в БД: потеря настроек больше не позволяет обойти подтверждение. Письма и SMS не заменяются демонстрационными кодами, коды не показываются в API или логах.

## Тема и уведомления

Темы light/dark/system сохраняются в rr_preferences и локально для первого кадра. При входе настройки загружаются из аккаунта. Переключение системной темы и синхронизация между вкладками поддерживаются. Игровые иллюстрации сохраняют собственные цвета.

Уведомления хранятся на сервере в rr_notifications, доступны через колокольчик и отмечаются прочитанными только своим пользователем. События: заявка/принятие дружбы, приглашение от друга, старт партии. Выключение отключает новые уведомления, прежняя история сохраняется. Ограничено 100 последними записями. Проверка обновлений выполняется при открытом сайте; фоновые системные push-уведомления и напоминания при закрытом браузере не реализованы.

## Проверки

Автотесты проверяют подтверждение регистрации, срок/попытки/одноразовость кодов, отсутствие открытого кода в БД, сброс пароля и завершение сеансов, отсутствие ложного сообщения отправки при отключённом сервисе. Проверены права на уведомления, их отключение и настройки темы. Браузерный сценарий проверяет тему после перезагрузки и на другом устройстве, центр уведомлений и мобильные размеры. Реальная доставка проверяется отдельно после сохранения API-ключа владельцем.
